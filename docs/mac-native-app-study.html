B-guru for Mac 検討

体制: architect／macOS UX デザイナー／security-reviewer／devils-advocate（Claude サブエージェント）、Safari Web アプリの仕様調査（Web 検索）、会員ペルソナ5名のパネル（自宅フリートのローカル GLM）。主要な事実は Claude がコードで確認しました。実装はまだしていません。

問い: ネイティブ版は PWA を圧倒的に超えるか。

答え: 本体ウィンドウでは超えません。超えるのは「作業を止めずに覗く」と「横に置いておく」の2場面だけです。macOS の Safari「Dock に追加」した Web アプリは、Web Push、Dock バッジ、Dock の右クリックショートカット、集中モード、閉じているときの通知受信、外部アプリからのリンクを Web アプリで開く挙動まで、すでに備えています。本体を WKWebView で作り直しても、PWA とほぼ同じ体験になるうえに Web Push を失うので、むしろ損になります。

推奨: 本体は PWA のまま磨き、ネイティブは「B-guru チャット専用アプリ」として切り出す。チャットは1部屋だけで、メッセージは24時間で消え、機能の面も小さいので、フルネイティブで作っても追従しきれます。しかも PWA が苦手なこと（最前面の小窓、ホットキー、通知からの返信）が、ちょうどチャットで一番効きます。さらに現状、チャットの @メンションはどこにも通知されていないので、PWA と重ならない穴を埋めることになります。まず運営者専用の試作を作って2週間使い、判定します。

チャット専用アプリ案（推奨）

途中で出た「チャットだけを切り出したメッセージアプリ」案を、コードで確かめた事実と照らし合わせました。上の「相棒」案より筋が良い、というのが結論です。

チャットアプリで PWA を超えるところ

  • どこからでも話せる: ⌃⌥B でチャットの小窓が開き、入力欄にすぐフォーカスが入る。⏎ で送信し、Esc で元の作業に戻る。
  • 横に置いておける: 最前面に固定でき、全 Space に表示でき、非アクティブ時は少し透明にする。配信中に OBS の上に置いておける。
  • メンションに気づける: @メンションを通知し、通知の上でそのまま返信できる。吠える音はメンションのときだけ鳴らす。
  • Mac らしい入力: 日本語変換中の ⏎ を誤って送信しない。⌘↑ で自分の直前の発言を編集する。画像のドラッグ&ドロップ。リアクションはクリックで。どれもネイティブの入力欄なら素直に作れる。
  • 状態がすぐ見える: メニューバーのビーグルの姿勢と Dock バッジでチャットの未読を表す。在席はウィンドウが見えているときだけにする。

進化に追従するための約束

  • チャットアプリが依存するのは /api/agent/chat* の契約だけ。サーバーは apiVersion と capabilities（例: reactions、customEmoji、edit、images）を返す。
  • アプリが知らない種類のメッセージや機能は、「B-guru で開く」リンク付きの簡易表示にして壊さない。新機能は Web 版に先に出て、需要が見えてからアプリに入れる。
  • Web 側では、チャット送信ロジックを route から src/lib/chat.ts に寄せ、Web 版とアプリの両方が同じ関数を通るようにする。契約テストを vitest に追加する。
  • SwiftUI で書くので、需要があれば同じコードで iPhone 版のチャットにも広げられる。会員は iPhone 中心の可能性が高いので、将来の伸びしろになる。

試作の判定基準をこの数字で置き換えます: 運営者が2週間使い、その後に希望者へ配布した段階で、チャットの1日の発言数（基準 約19件）と発言者数（基準 約8人）が目に見えて増えるか。増えなければ PWA 側でチャットの通知を整えるだけにとどめます。

リスク

  • 発言の少なさ: 1日 19件ほどなので、アプリだけで会話が増えるとは限らない。最初に効くのは、メンション通知と、すぐ返信できる手軽さ。
  • チャットだけのアプリにすると、タイムラインから人が離れるおそれがある。アプリの上部に「自分宛ての返信 N件 ▸ B-guru で開く」の1行だけ残し、タイムラインは PWA に誘導する。
  • 相棒にメンション通知を持たせるなら、トークンの短命化と OTP は前提になる（下のセキュリティ節）。

比較した案: PWA 本体 ＋ メニューバー相棒

チャット専用アプリ案の一つ前に検討した構成です。考え方（本体は PWA、ネイティブは小さく）はそのまま引き継いでいます。チャットに絞った方が、作る理由も、触り心地を磨く対象もはっきりします。

 ┌──────────── PWA（Safari Web アプリ）── 本体。今まで通り毎日進化 ───────────┐
 │ フィード / スレッド / 投稿 / 部活 / 設定 / ビーグル演出 / Web Push / バッジ │
 └───────────────────────────────▲───────────────────────────────────┘
                                 │ https://bsm.backspace.fm/#/post/123 を開く
 ┌─────── メニューバー相棒（SwiftUI、小さく保つ）────────────────────────────┐
 │ ① 覗く: ⌃⌥B でポップオーバー → 自分宛て・新着・チャット最新 → Esc で戻る   │
 │ ② 横に置く: 最前面のチャット小窓（WKWebView で ?compact=1 を表示）          │
 │ データ: /api/agent/summary と個人宛てストリーム（agent API・Keychain）      │
 └──────────────────────────────────────────────────────────────────┘
  • 相棒は本体を持たない。項目をクリックすると URL を開き、Sequoia 以降はそれが Web アプリに渡る（ハッシュ #/post/123 が保たれるかは未確認。Web アプリを1つ作って open で試せば1分で確定する）。
  • 通知は PWA の Web Push に任せる（二重通知を避ける）。通知の上で返信したい需要が試作で確かめられたら、v2 で相棒側に移すことを検討する。
  • チャット小窓だけは WebView。中身は Web 側の ?compact=1 表示なので、チャットの新機能はそのまま入る。
  • 相棒が依存するのは UI ではなく agent API の契約だけ。サーバーは apiVersion と capabilities を返し、相棒は知らない項目を無視し、無い機能は隠す。小窓に何を出すかもサーバー側で切り替えられる。

相棒の触り心地（専門家と会員パネルの合意点）

  1. 覗いて戻る: ポップオーバーは 0.18 秒で開き、0.12 秒で閉じる。作業中のアプリからフォーカスを奪わない。会員パネルの5人全員がこれを一番の価値に挙げた。
  2. 状態はビーグルの姿勢で表す: 寝ている＝静かな時間、座っている＝通常、耳が立つ＝新着、吠える＝自分宛て（0.5 秒だけ）。点滅、バウンス、Dock の跳ねは使わない。
  3. 自分宛てが主役: 新着は折りたためるようにし、読み専の会員向けに「続きから読む」を付ける。入力欄はフォーカスしたときだけ広げる（常に出ていると発言を促されているようで居心地が悪い、という声があった）。
  4. アクセシビリティ（パネルの a11y ペルソナの指摘）: ホバーしないと出ないボタンは使わない。アイコンの状態は accessibilityLabel にも入れる（例:「B-guru、自分宛て2件」）。Dynamic Type に合わせて高さが伸びるようにする。開いたときのフォーカス位置を決めておく。
  5. 配信モード（ホスト役の指摘）: チャット小窓を最前面に固定し、静かな時間はローカル通知だけに効かせる。ホスト役はこの小窓を MVP に入れてほしいと求めた。
  6. 「おはようだわん。夜のあいだに 3件（自分宛て 1件）」のように、朝に1行でまとめる。ビーグルの一言はローカルのテンプレートで作り、表示の頻度を下げ、オフにもできるようにする。

やめた案と理由

  • WKWebView で本体を包むアプリ（最初のチーム案）: 本体の体験は PWA と大差がないのに、Web Push が使えなくなる（WKWebView は Web Push に非対応）。WKWebView 固有の回避策が page.tsx に溜まっていく危険もある。PWA を基準にすると、損のほうが大きい。
  • フル SwiftUI: 直近30日で 261 コミット、そのうち 159 が page.tsx への変更。一人開発では Web の速さに追いつけない。
  • Electron / Tauri: PWA より重く、ネイティブらしさも足りない。

どの案でも先に直すべきこと（セキュリティ）

  • high・確認済み ログインがメールアドレスだけで、OTP なしにセッションを発行している（src/app/api/auth/request/route.ts:49）。そこから 30 日有効の agent token も作れる。相棒が長期トークンを持つ前に OTP を入れる（otp_codes テーブルは定義済み）。
  • high・コードで確認、本番では未検証 認証前のレート制限が実質的に効いていない。src/lib/agent-auth.ts:349 の ON CONFLICT (key, window_start) に対し、一意制約は key だけなので PostgreSQL がエラーを返し、catch が true を返して素通りになる。
  • medium Cookie セッションは発行後に会員資格を再確認していない。Web Push は全購読者に本文の先頭60字を送っていて、退会者にも届く。CSP が未設定。
  • 相棒用のトークンは短命にし、refresh rotation と、読み取りと通知だけの native スコープにする。Keychain には ThisDeviceOnly で保存し、失効は既存の settings-devices を使う。
  • 確認済み /api/posts/stream は接続中を「オンライン」とみなすので、相棒が常時つなぐとずっと在席表示になる。相棒には presence に影響しない個人宛てストリームを別に用意する。
