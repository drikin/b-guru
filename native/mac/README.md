# B-guru Chat for Mac（試作）

B-guru のチャットだけを切り出したメニューバー常駐アプリ。本体（タイムライン等）は PWA のまま。
検討の経緯は `docs/mac-native-app-study.html`。

## 使い方
- メニューバーのビーグルをクリックすると開閉（開くときは常に最前面）。**最後に見ていたタブで開く**（チャットならその入力欄にカーソル）。固定していて後ろに回っているときは前に出す
- **⌃⌥B** も開閉。こちらは今までどおり**いつもチャットを開き**、入力欄にカーソルが入っているので、そのまま打って Enter で送れる（右クリックメニューの「チャットを開く」も同じ）。Esc で閉じる。固定していなければ他をクリックで隠れる
- **右 ⇧ を素早く 2 回**でも開閉（2026-10-25。ビーグルのクリックと同じく最後のタブで開く。⋯ メニュー／右クリックメニューの「右 ⇧ を 2 回押してパネルを開閉」、既定はオン）
  - 右 ⇧ だけ（keyCode 60・機種依存ビット 0x04）。1 回目を離してから 0.35 秒以内に 2 回目、どちらも 0.35 秒以内に離す。左 ⇧・⌘ などと一緒・あいだにほかのキーやクリック・長押しは数え直し（`DoubleTapDetector`、`DoubleShift.swift`）
  - アプリが前（パネルに入力があるとき）は許可なしで効く。ほかのアプリが前のときは NSEvent のグローバル監視なので macOS の「入力監視」（またはアクセシビリティ）の許可が要る。
    アプリの中で初めて効いたときに 1 回だけ案内を出し、許可がまだのあいだはメニューに「ほかのアプリが前でも使う（入力監視を許可…）」が出る。許可されたら 5 秒以内に監視を付け直す（効かなければ再起動）
  - Secure Input（パスワード欄など）が入っているあいだは何もしない。打った文字は読まない（見るのは右 ⇧ と「ほかのキーが押されたか」だけ）
  - 開発のみ: `-doubleShiftSelfTest` で判定の単体テスト（失敗で終了コード 1）。後片付け: `defaults delete fm.backspace.bguru.chat rightShiftDoubleTap`・`rightShiftHintShown`
- 📌 で固定（他をクリックしても隠れない・全 Space・配信中に横に置く用途。位置を記憶）
- **パネルの大きさ・位置・タブを覚える**（2026-10-22）。閉じて開いても、アプリを再起動しても元のまま
- **文字の大きさ**（2026-10-24、老眼対策）: ⌘＋（⌘= ・JIS の ⌘; も）で大きく、⌘− で小さく、⌘0 で標準。⋯ メニューの「文字の大きさ」からも 90〜200% で選べる。パネルの文字すべて（本文・名前・時刻・リアクション・入力欄）が変わり、覚えておく。macOS には iPhone のような文字サイズの設定が無い（`dynamicTypeSize` は効かない）ので、アプリの文字はすべて `Font.app`（`shared/TextScale.swift`）を通す。新しく文字を足すときも `.font(.app(.caption))` のように書く。iPhone / iPad は今までどおり iOS の文字サイズに従う。開発のみ: `-textScale 1.5` で保存せずに試せる
  - 大きさ: 最後に自分で変えた大きさ（固定していてもいなくても）。300×320 より小さく・画面より大きくはしない
  - 位置: ドラッグして動かすまでは今までどおりビーグルの下に出る。一度動かすと、**そのディスプレイでは**次からその場所に
    出る（ディスプレイごとに覚える。ディスプレイの UUID で区別）。外付けを外した・解像度が下がった・Dock の位置が
    変わったなどで画面からはみ出すときは、見える範囲に収め直す（大きすぎれば縮める）。覚えていないディスプレイでは
    ビーグルの下。📌 で固定したパネルは今までどおり自分の位置（`NSWindow Frame BguruChatPinned`）を持ち、開くときに
    画面の中に収め直す
  - タブ: ビーグルのクリックでは、タイムライン／チャット／📻 の最後のタブで開く（以前は開くたびにチャットに戻っていた）。
    **⌃⌥B（と右クリックの「チャットを開く」）は今までどおりチャットを開いて入力欄にカーソル**。チャットの中は ☗・🎮 を開いていればまた開く。ルームはサーバーの状態に従う
    （入ると皆に見えるので、自分からは入らない）。📻 が使えなくなっていればチャットで開く
  - 設定のキー: `panelSize`（[幅, 高さ]）・`panelPlaces`（{ディスプレイの UUID: [左からの距離, 上からの距離]}）・
    `panelTab`（timeline / chat / jukebox）・`panelChatScreen`（text / room / shogi / minigame）。
    元に戻す: `defaults delete fm.backspace.bguru.chat panelPlaces`（位置だけ）、ほかも同様
  - 開発のみ: デモ（`-demoPanel`・`-selftest`）はこの設定を読み書きしない（本物のアプリと同じ設定を使うため）。
    `-demoPanel -panelMemory -panelMemoryCheck 1|2|3` で確認（1: 大きさを変えて閉じて開く・動かす・タイムライン・☗、
    2: 再起動後に同じか、3: 保存した位置が画面外・大きさが画面より大きいときに収まるか）。stderr に `[panel-memory] …`。
    後片付けは上のキー
- Enter 送信 / ⇧Enter 改行 / 空欄で ↑ = 自分の直前の発言を編集
- メッセージにマウスを乗せると吹き出しの角にボタンが出る: ❤️（1クリック）／😊（リアクションを選ぶ）／✏️（自分の発言を編集）
  - 右クリックメニュー、ダブルクリックで ❤️、空欄で ↑ で編集、も使える。編集中の吹き出しは緑の枠
- メニューバー: 未読があると犬が塗りつぶし＋件数、自分へのメンションがあると「@件数」
- 通知: @メンションは個別に（返信・❤️ 可、吠える音つき）。その他の新着は1つの通知にまとめて更新
  （「…（ほか 3 件の新着）」）。クリックでその位置へ移動してハイライト。チャットを開くと消える
- ⋯ メニューで設定: 通知（新着すべて / メンションだけ）、静かな時間（0:00〜7:00 は新着を通知せず、
  メンションは音なし）、Dock にも表示（未読バッジ）
- **試験的：ほかのステータスバーアイコンを畳む**（⋯ メニュー、またはビーグルの右クリックメニューでオン。既定は切）
  - オンにするとビーグルの左に区切り（‹）が出る。隠したいアイコンを **⌘ を押しながら区切りの左へドラッグ**（初回だけ説明が出る）
  - 畳むと区切りより左のアイコンは macOS の「«」（あふれ）に入り、メニューバーは「« ビーグル」になる（« を押せば中身も開ける）
  - 出し入れ: ビーグルに**カーソルを乗せて 0.4 秒止める**と出す（通り過ぎただけ・ボタンを押している・⌘ を押している・メニューが
    開いているときは出さない。⋯ メニュー／右クリックメニューの「カーソルを乗せたら出す」で切れる、既定はオン）。ほかに、ビーグルを
    **⌥（option）＋クリック**、または区切り（‹）のクリック。ふつうのクリック・右クリックは今までどおり
    - 乗せて出したあとはメニューバーの上にいるあいだ出したまま（カーソルがビーグルから外れても畳まない）。畳んだあとは、カーソルが
      一度ビーグルから外れるまで乗せても出さない（出す→外れる→畳む→また乗る、の繰り返しを防ぐ）
  - 3 本指タップは非対応: macOS はステータスアイテムに 3 本指タップを届けない（quickLook もタッチも来ない。26.7.1 で確認）
  - 出したあと 10 秒たつか、メニューバーからマウスを離すとまた畳む（メニューバーの上にマウスがある・ボタンを押している・
    メニューが開いているあいだは待つ）。オフにする／アプリを終了すると区切りを消して元に戻る
  - ⌘＋クリックにしなかったのは、macOS 27 では ⌘ を押してステータスアイコンを押すとシステムが並べ替えに使い、アプリに届かないため
  - **しくみと注意**: macOS 27 は区切りの幅を大きくしても左のアイコンを画面の外へ押し出さない（大きすぎると区切りが外されて
    何も隠れない）。そこで区切りの幅を毎回測って合わせ、区切りごと « に入る幅にしている（前面のアプリ・画面の構成・ビーグルの幅が
    変わったとき、と 20 秒ごとに確認。アプリごとの幅を覚えるので、2 回目からはほぼ 1 回で決まる）。メニューの長いアプリが前に
    あるときは macOS がビーグルごと « にしまうので何もしない。**macOS の仕様外の動きに頼るので、将来の macOS で効かなくなりうる**
    （そのときは何も隠れないだけで、区切りが残る・アイコンが消えることはない）
  - 開発のみ: `-demoPanel -collapseTest` で自分のダミーのアイコン（★ ♥）を区切りの左に置き、分散通知
    `fm.backspace.bguru.chat.debugCollapse`（object に toggle / collapse / expand / settingOn / settingOff / hoverOn / hoverOff / unread / frames / quit）で
    操作できる。stderr に `[collapse] …` `[statusbar] …`。後片付け: `defaults delete fm.backspace.bguru.chat collapseOtherStatusItems`・`collapseHintShown`・`collapseRevealOnHover`、
    `…/Diagnostics/statusbar.log`
  - **診断の記録**: この機能がオンのあいだ、設定のオン・オフ、どの合図で切り替えたか（ホバー・⌥クリック・区切りのクリック）、
    畳む／出す／測り直しの結果を `statusbar.log` に 1 行ずつ残す（最大 200 行、個人情報なし。hangs.log と同じフォルダ）。
    うまく畳めないときは次で送ってもらう:
    ```bash
    tail -n 40 ~/Library/Containers/fm.backspace.bguru.chat/Data/Library/Application\ Support/Diagnostics/statusbar.log | pbcopy
    ```
- **メニューバーのビーグルは左向き**（2026-10-22。ティッカーの文字が左へ流れるので、左を向いて吠えて送り出す絵に）。SF Symbols の
  dog / dog.fill（22×17pt）を左右反転し、顔の前（左）に 8pt の余白を足した 30×17pt のキャンバスに描く（`BeagleIcon`）。余白は通常の
  ときもあるので、吠えても幅は変わらない。未読の数は数字の幅をそろえた字（1→2 で幅が変わってビーグルが横にずれない）。
  変えたのは Mac のメニューバーだけ（アプリのアイコン・iOS・Android・Web はそのまま）
- **新着でビーグルが吠える**（⋯ メニュー／右クリックメニュー「新着でビーグルが吠える」、既定はオン）
  - 1 回の吠えは約 1.2 秒（0.15 秒ごとに 8 コマ）：首から前を上へ 1pt 引き伸ばして頭を上げ、口を大きく開け、余白に太い「ワン」の線を
    放射状に 3 本（伸びる）、最後に「!」。新着・お知らせは 2 回、メンションは 3 回。足元・後ろ足・しっぽは全コマ同じ（画面の差分で確認、
    ボタンの frame も変わらない）
  - 刻みはタイマー（Core Animation は macOS 26 のメニューバーで動かなかった前例）。終わったら必ず最新の状態（未読・接続）の絵に戻す
  - 吠えないとき: チャットを見ているとき、静かな時間、「視差効果を減らす」がオンのとき、前に吠えてから 10 秒以内。
    ティッカーがオンなら流れ始めと同時に吠える。statusbar.log に「吠えた（種別）／吠えない（理由）」
- **負荷に合わせてビーグルが走る**（⋯ メニュー／右クリックメニュー「負荷に合わせてビーグルが走る」、既定は切。RunCat 風）
  - 2 秒ごとに CPU（host_processor_info、全コア）を測り、直近 3 回の平均で決める。その下の「GPU の負荷も見る」（既定は切、走る機能が
    オンのときだけ出る）をオンにすると GPU（IOKit の IOAccelerator「Device Utilization %」。サンドボックスのままで読める）も読み、
    高いほうで決める（オフのときは IOKit も読まない）。速さは: 15 % 未満は座ったまま（タイマーなし）、15〜40 % は歩く（0.25 秒ごと）、40〜70 % は走る
    （0.12 秒）、70 % 以上は全力（0.06 秒）。視差効果を減らすがオンなら走らない。吠えるときは止まって吠え、終わったら再開
  - 走るコマは 4 枚（伸びる・着地・縮む・けり出す）。脚は描き足さず、記号の脚の部分（お腹の線より下）だけを付け根の高さを軸に前後へ傾ける（前脚と後ろ脚は逆向き、±9°・±24°）。付け根でずれが 0 なので継ぎ目が出ず、脚の丸み・線の太さ・抜きは元の絵のまま。宙に浮くコマだけ犬ごと 1pt 上がる。線／塗りの両方
  - オンのあいだは、ビーグルの絵（座る・走る・吠える）をすべてボタンに重ねたレイヤーで描く（ボタンには同じ大きさの透明な絵）。
    ボタンの画像を差し替えると毎回配置の計算が走り、全力で CPU 5〜6 % になったため。レイヤーなら全力でも 0.9 % 未満
    （試した値: 座る 0.1 %・歩く 0.4 %・走る 0.6 %・全力 0.9 %）。システムが描く絵とは縦が 1px ずれることがあるので、
    オンのあいだは座っている絵もレイヤーで描いて、切り替えで位置が動かないようにしている（横ずれ 0 を画面の差分で確認）
  - GPU を既定で見ないのは、写真の解析（mediaanalysisd）などで GPU が普段から高い Mac があり、何もしていなくても走りっぱなしに
    なるため（試した Mac では 70〜90 % のときがあった）
- **メニューバーのティッカー**（⋯ メニュー、またはビーグルの右クリックメニューで「メニューバーにティッカーを流す」。既定は切）
  - チャットの新着（「名前：本文」1 行。改行・長文は詰める。写真は「📷 写真」。自分の発言は流さない）、自分へのメンション（太字、
    「@ 名前：本文」）、ビーグルのお知らせ（☗ の見どころ・対局カード、散財ダッシュなど。部室の出入りは流さない）を、ビーグルの
    アイコンの左に 1 件ずつ流す。1 件 6〜8 秒（右から左へ 1 回、短いものはその場に 6 秒）。続けて来たら順に（待ちは最大 5 件、古いものは捨てる）
  - 「名前だけ（本文を出さない）」: 「コバン さんの新着」「@ ゆう さんからメンション」だけ（お知らせは会員の発言ではないので本文を出す）
  - ティッカーの部分をクリックするとチャットを開いてその発言へ。アイコンの部分のクリック・右クリック・⌥クリック・ホバーは今までどおり
    （ホバーはアイコンの部分だけで見る）
  - 流さないとき: チャットを開いて見ているとき（開いたら流れているものも止める）、静かな時間（0:00〜7:00、設定がオンのとき）。
    macOS の集中モード（おやすみ）は、読むのに専用の権限（Focus Status）と許可のダイアログが要るので見ていない
  - しくみ: ビーグルの NSStatusItem 自体を左へ広げる（タイトルの先頭に幅だけの透明な添付、画像をタイトルの右へ）。広げた所に重ねた
    ビュー（クリックは素通し）の Core Animation のレイヤーで文字を動かすので、メインスレッドを使わない。流していないときはタイマーも
    アニメーションもない（試した値: アプリの CPU は流していないとき 0.1 %、流しているとき 0.1〜0.3 %）
  - 畳む機能で畳めているときは、区切りの幅を同じだけ縮めてからビーグルを広げる（合計の幅が変わらないので « の中のアイコンは出てこない。
    最大 300pt、区切りが収まった幅から余裕を引いた分まで）。戻すときも同じ処理の中で区切りを戻す。畳む機能がオフ・出しているときは
    最大 200pt で、広げたあとビーグルが押し出されていないか確かめ、だめなら戻す（「空きなし」。未読の数だけ）
  - VoiceOver には 1 件ずつ 1 回読み上げる（アナウンス）。statusbar.log に「ティッカー: 表示（種別・幅）／空きなし／クリック」
    （本文は書かない）
  - 開発のみ: `-demoPanel -tickerTest`（パネルは開かない、静かな時間も無視）＋分散通知（上と同じ名前）の
    msg / mention / notice / photo / long / room / burst / tickerOn / tickerOff / namesOnly / namesFull /
    forceLight / forceDark / forceNone（文字色の外観を固定して見本を撮る）。`-collapseTest` と一緒にも使える。
    後片付け: `defaults delete fm.backspace.bguru.chat menuBarTicker`・`menuBarTickerNamesOnly`・`menuBarBark`・`menuBarRunner`（barkOn / barkOff・runOn / runOff・gpuOn / gpuOff、load0 / load25 / load55 / load90 / loadReal で負荷を固定）
- **AI がタイムラインのおすすめを教える（この Mac の中だけで動きます）**（⋯ メニュー／右クリックメニュー、既定は切。macOS 26 以降で
  端末内 AI＝Foundation モデルが使えるときだけ選べる。使えないときは理由を 1 行: 未対応の Mac・Apple Intelligence がオフ・準備中・日本語未対応）
  - 1 時間ごと（前回より新しい投稿があるとき。低電力モード・静かな時間・チャットを見ているあいだはしない）、未読・自分のでない・まだ
    おすすめしていない投稿を最大 30 件、6 件ずつ採点（合う度 0〜10・40 字以内のひとこと、構造化出力）し、7 点以上の最上位 1 件だけを
    ティッカーで「🐶 おすすめ：○○さん『ひとこと』」（1 回吠える）。クリックでそのスレッドを開く。1 日 6 件まで、同じ投稿は二度出さない
  - ティッカーがオフでも、おすすめだけは流す
  - 興味の材料: 自分の投稿・リアクションした投稿・この Mac で開いたスレッドと返信したスレッド（オンのあいだだけ、最大 200 件）・
    その部活。1 日 1 回 AI で 200 字以内の「興味のまとめ」にする（少ないときは題材をそのまま）。記録は
    `~/Library/Containers/fm.backspace.bguru.chat/Data/Library/Application Support/AIPicks/memory.json`（設定をオフにすると消す）。**投稿の中身・興味の記録は
    サーバーにも外部にも送らない**。statusbar.log には本文を書かない（「出した（点・件数・秒）」「失敗（理由の種類）」だけ）
  - AI の失敗（ガードレール・文脈超過・未対応の言語など）は黙って次回へ。試した値（macOS 27.0.1、M3 Max）: 30 件の採点に 47〜58 秒
    （6 件で 4〜17 秒）、興味のまとめ 2 秒。そのあいだ端末内 AI のサービス（TGOnDeviceInferenceProviderService）が CPU 約 20 %・
    メモリ 1.4〜1.8 GB、アプリ自身は CPU 2〜3 %
  - 開発のみ: `-demoPanel -tickerTest -aiPicksNow`（いろいろな話題の投稿 30 件と興味の材料で、すぐ 2 回回す。オフライン）。
    コンソールに採点（点・投稿 ID・ひとこと・所要時間）。後片付け: 上の AIPicks フォルダを消す
- **アシスタント：ウインドウの変化を知らせる（試験的）**（右クリックメニュー／⋯ メニュー。サーバーの capabilities `features.mac_assistant`
  が true のときだけ出る＝最初はオーナーだけ。古いサーバー・false では出ない。端末内 AI が使えない Mac では選べず理由を 1 行。既定は切）
  - オンにするときは必ず説明と同意（どちらのメニューからでも同じ）：ほかのアプリのウインドウを Mac の中の AI が読む（ほかのウインドウの
    後ろに隠れているウインドウも）・画像も文字も外に出さない・「違う」の例は画面の文字の一部（1 件 60 字まで・最大 10 件）を Mac の中に
    保存しオフで消える・画面収録の許可が要り、オフにした後はシステム設定 → プライバシーとセキュリティ → 画面収録で外せる。
    オフにすると記録を消し、許可の外し方を案内する
  - 画面に出ているほかのアプリのウインドウを巡回して見張り、表示が変わったら変わった所の文字を読み（Vision）、端末内 AI
    （Foundation Models）が「知りたいこと」に当たるかを判断する。当たれば、ビーグルが吠えて「🐶 アプリ名：何が起きたか」
    （AI の推測であることはメニューの「最近の知らせ」とパネルの 1 行のヘルプに書く。アプリ名と末尾の決まり文句は理由から外す）。パネルが見えていればヘッダーの下に 1 行（クリックで前面、× で閉じる）、見えていなければティッカー、
    静かな時間は保留して明けたら最新の 3 件だけ。「名前だけ」の設定・画面共有／配信中らしいとき（会議アプリが前面、OBS・Streamlabs・
    Ecamm Live が起動中）はアプリ名だけ。共有・配信中かどうかはアプリの一覧から推測しているだけなので、配信・画面共有をする日は
    「名前だけ」の設定と併せて使い、見張りを一時停止にしておくのが確実クリックでそのアプリを前に出す（アプリ単位。ウインドウ単位で一番前に出すにはアクセシビリティの
    許可が要るので、今回はしない）
  - 見張らないもの: 今前面のアプリ・B-guru 自身・システムの部品・小さすぎるウインドウ・除外するアプリ（既定で 1Password・Bitwarden・
    キーチェーンアクセス・パスワード・システム設定。銀行のアプリなどは「除外するアプリ…」で足す）・題がプライベートブラウズらしい
    ウインドウ。最小化・別のスペースのウインドウは撮れないので見張らない
  - 巡回: 1 ウインドウずつ小さく撮って前と比べ、全体を数秒〜十数秒で一巡（ウインドウが多いほど間隔を伸ばす）。変化したウインドウは
    1 回おきに寄り道して見直し（寄り道は一巡の時間に数えない。3 秒以上変わり続ける窓は寄り道しない）、1 秒落ち着いたら読む
    （一巡はおよそ 4 秒、窓が 10 個を超えると窓の数 × 0.4 秒。AI の判定を待つあいだも見回りは止めない）。
    窓ごとに今見えている行だけを持ち（基準を作るときに窓全体を 1 回読む。ためない）、変化したら窓全体を読み直して、前と今の行を
    回数つきで比べ（文字認識の揺れは、完了・成功・失敗・エラーなどの語の組が同じで 2 文字ずつの重なり 7 割以上のときだけ同じ行と
    みなす。「すべて成功しました（42件）」→「3件失敗しました（42件）」は新しい行。照合はメインスレッドの外。窓全体は幅 2048 画素まで）、増えた行だけを新しい文字とする（元に戻っただけ・
    前からあった文字・長い行の一部が変わっただけは数えない。同じ文が一度消えて 2 回目に出たら新しい文字）。変化した範囲は
    「変化が起きたか」の判定にだけ使う。絵は比べる用の小さい灰色だけを持つ。前の行が読めなかった窓は、その変化は判定せず次の変化から。一巡した後に、この
    世代で初めて見たウインドウ（ダイアログ・承認依頼）は全体を読んで判定に回す（前面だった・最小化していた・別のスペースにあった窓が
    戻っただけは「新しい窓」にしない）。大きさが変わった
    （画面の構成・Retina 間の移動）ら判定せず基準を作り直す。小さい変化・時刻や数字だけ・新しく出た意味のある文字が無い変化
    （消えただけ・短い状態語に戻っただけ・題の文字だけ）は判定に回さない。20 秒以上動き続けるウインドウは見送る。オフ・一時停止・
    スリープ・画面のロック・ユーザーの切り替えで止まり、処理中の 1 件も知らせない（世代番号）。一時停止中は絵を捨てる
  - 判断: 変化の種類を AI に選ばせ（完了・エラーや失敗・承認や確認の依頼・持ち主宛て／広告・時刻や進み具合・天気やニュース・意味の
    ない変化）、アプリ側で決める。持ち主宛ては持ち主の名前（Mac のユーザー名・B-guru の表示名）が語として出るか @ が持ち主・全員宛て
    のときだけ（文字認識で @名前 の後ろの空白が消えても名前で始まれば、3 字以上の名前は 1 文字の読み違い「@koh」→「@kon」も
    持ち主宛て。英字の名前に空白なしで日本語が続くなど読み取りが確かでない @ は、ほかの人宛てとして見送らない）。依頼・承認も、ほかの人が宛先と明示されていれば（@ほかの人・「〇〇さん」、全角はそろえる）見送る。AI の理由が
    「関係ない」と矛盾すれば知らせず、空疎（「新しい文字が出た」など）なら文字に完了・失敗・承認・依頼などの手がかりがあるときだけ。
    AI が「完了」「エラーや失敗」を選んでも、文字に完了・失敗などの語が無ければ知らせない。見出しでニュース・速報・運勢・占い・天気・
    広告と分かる行だけなら、AI が何を選んでも知らせない。進み具合（「〜中です」「45%」「更新」「残り」）だけの文字は、強い手がかりが
    無ければ知らせない。手がかりの語は、英語は単語の切れ目で一致させ（incomplete・autocomplete・successfully・errors に当てない）、
    否定（0 errors・no errors・エラーなし・エラー 0 件。0 を O と読んだものも）は除く。
  - 決まりでの上書き（最小限）: AI が「意味のない表示の変化」を選んだときだけ（試験で「Build succeeded」に AI が選んだのは「完了」か
    これ。広告・おすすめ、天気・ニュースは上書きしない）、広告らしい語が無く、ほかの人宛てでなく、持ち主の名前（一斉宛ての @here・
    @channel・@everyone・@all は数えない）か、40 字以内の短い行に強い手がかりがあれば知らせる。上書きした知らせは自動で前に出さず、
    理由は画面の文字でなく決まった文（「完了・失敗などの文字が出ました」「あなた宛てらしい文字が出ました」）
  - 件数・頻度の上限は設けない（オーナー決定 2026-10-22：本当の変化なら何件でも知らせる。絞るのは精度だけ）。同じ文がまた出たら、
    それは新しい変化として知らせる（見えたままの文は行の差で数えないので、重ねて知らせない）。最近の知らせのメニューの
    「このアプリは知らせない」で、1 クリックで除外リストに入れる（「除外するアプリ…」で外せる）
    AI を呼ぶのは 1 ウインドウ最短 10 秒に 1 回（間隔待ちの変化は捨てずに保留に足し、明けたらまとめて判定）
  - 学ぶ: 最近の知らせ（5 件。「名前だけ」の設定ではアプリ名だけを出す）から「違う」「合ってた」を選べる。「違う」と同じアプリ・同じ変化（数字を除いた文字が一致かよく似ている）
    は AI に渡す前に見送る。1 週間の件数をメニューに出す
  - 自動で前に出す（既定は切）: キーボードとマウスが 30 秒以上無操作・パスワード入力中でない・ブラウザ（Safari・Chrome・Edge・Arc・
    Firefox など）でない・画面共有／配信中でない・静かな時間でない（集中モードは読めないので代わり）・60 秒以内に出していない・
    そのアプリを使っていない、のときだけ（画面の文字で誘導されないように）。それ以外は知らせるだけ
  - 保存: `~/Library/Containers/fm.backspace.bguru.chat/Data/Library/Application Support/Assistant/memory.json`（「違う」の例と件数、
    オフで消す）。statusbar.log・開発用の記録にほかのアプリの題や文字は書かない（アプリ名・判定・時間だけ）
  - 試した値（M3 Max・macOS 27、テスト用の窓）: 判断 0.9〜1.9 秒。見張りだけのアプリの CPU 0.5 %（窓 3 つ）・1.5 %（窓 30 個）、
    起動直後の 30 秒（窓 30 個を一巡で読む）は 5.7 %。窓 30 個では一巡 12 秒で、変化から知らせるまで 5〜17 秒。
    メモリ（RSS）は窓 3 つで約 220 MB・窓 30 個で約 250 MB（絵は小さい灰色、文字は今見えている行だけを持つ）
  - AI を呼ぶ間隔（1 窓 10 秒）を待つあいだの変化も、落ち着くたびに窓全体を読み（1 窓 5 秒に 1 回まで）、新しく出た行を足し合わせて、
    間隔が明けたらまとめて判定する（途中で出て消えた文字も取りこぼさない）
  - 残る制限: 一巡の間隔（およそ 4 秒。窓が 10 個を超えると窓の数 × 0.4 秒）と落ち着くのを待つ 1〜2 秒より短く表示されて消える文字は、
    取りこぼすことがある。同じ文でも、AI の判定が
    揺れることがある
  - 開発のみ: `-demoPanel -tickerTest -assistantTest [-assistantTestWindows N]` で自分のテスト用の窓だけを見張る（ほかのアプリは読まない）。
    `-assistantSelfTest` で絞り込み・宛先・手がかりの語の単体テスト（失敗で終了コード 1）。`awForceKind:<種類>` で次の 1 回だけ AI の種類を差し替える。`awMute`（このアプリは知らせない）。分散通知は `BGURU_DEBUG_CHANNEL` を付けた名前で
    （ほかの試験中のアプリと混ざらないように。送る側も同じ値）。`aw:<A|B|C|Wn>:text:<文>`・`aw:new:<文>`（新しい窓）・`aw:A:clock`・
    `aw:B:blink`・`aw:A:still`・`awWrong`／`awRight`・`awAutoOn`／`awAutoOff`・`awPause`／`awResume`・`awOff`／`awOn`・
    `awQuietOn`／`awQuietOff`・`awFrontCheck`・`awMemory`・`showPanel`／`hidePanel`。後片付け: 上の Assistant フォルダと `assistant*` の defaults

## タイムラインの表示（Web と同じ決まり、2026-10-22）
決まりの正本はサーバーの `src/lib/timeline-display.ts`（docs/timeline-spec.md）。アプリは `include=display` の `display` を
描き、無いとき（古いサーバー）は `native/shared/PostDisplay.swift` の `TimelineRules` が同じ答えを出す（下の例題で確認）。
- 長文: 本文が 500（JS の length＝UTF-16）を超えたら先頭 500（手前で絵文字が割れるときは 499）で切り、下を薄くして
  「続きを読む」。開いたら「閉じる」。画像・リンクのカード・動画・音声は畳んでも全部出す
- 画像: 切り抜かない。1 枚は元の比率で最大幅 360（高さは 480 まで。それより縦長なら幅を狭めて比率を保つ）。2 枚は 2 列、
  3〜5 枚は 3 列で、Web・Android と同じ「同じ幅の列」（セルの幅＝(幅−隙間)/列数、高さ＝幅/縦横比、上ぞろえ、行の高さは
  その行で一番高いセル）。1 マスの高さは幅の 2 倍まで（仕様書 §1・Android と同じ。それより縦長は画像をセルの中に収め、背景は透明）。横長に上限はない
- リンクのカード: 画像は切り抜かず元の比率、高さは 240 まで（YouTube は 16:9・最大幅 480）
- スレッドを開いているあいだ、裏の一覧の行の高さは変えない（届いた画像の比率・動画の最初のコマは閉じてから反映。
  10/21 の固まりと同じ形を避けるため）
- 動画: 最初の 1 コマに ▶。押すとその場で再生（AVPlayer、最大 560×420）。最初のコマは Wi-Fi など高価でない回線
  （NWPathMonitor の isExpensive・isConstrained が false）のときだけ取りに行き、それ以外は ▶ と「動画」だけ。
  標準のボタンで再生し直しても「一度に 1 つ」を守る（timeControlStatus を見る）。音声: 小さなプレーヤー（ジュークボックスの
  回は今までどおりジュークボックスで）。どちらも一度に 1 つ。ジュークボックスが鳴り出すと止まり、鳴らすとジュークボックスを止める。
  アップロードしたファイルにはアプリのトークンを付けて取りに行く（自分のサーバーだけ。先に 1 バイトだけ取りに行って
  リダイレクトの行き先を確かめ、別のホストに行くならトークンを付けない）
- GIF: 見えているあいだだけ動かす（画面外・別のタブ・パネルが閉じている・スレッドを開いているあいだは止める）。
  コマは 1 枚ずつ表示する大きさで読み、全部で 12 MB 以内なら覚えておく
- リアクション: 件数の多い順、同数は絵文字の UTF-16 順。付けた人は Web と同じ「❤️ 14人」＋12 人まで＋「他N人」
  （Mac はホバー、iPhone は長押し）
- メンション: 会員名に一致する @ だけ緑の太字＋薄い緑の角丸（macOS 15 / iOS 18 から。それより前は角なし）。自分宛ても同じ見た目
- Spotify はカードのまま（Web の埋め込みプレーヤーは WebView が要るため）。`#/user/…` のリンクはまだ文字のまま
- 開発のみ（オフライン）: `-selftest DIR -demo -timelineShots`（例の投稿を幅 380／720・ライト／ダークで DIR/parity-*.png）、
  `-selftest DIR -demo -timelineCheck [-demoPosts 300]`（GIF・動画入りの長い一覧を下まで送って戻す。メインスレッドが 5 秒
  止まれば失敗。GIF が動いているとき／無いときの CPU も出す）、`scripts/timeline-fixtures.sh`（リポジトリの
  `src/lib/__tests__/fixtures/timeline/posts.json`・`expected.json` をアプリの入れ物にコピーして `-timelineFixtures`：アプリ内の
  計算が全例題で期待値と同じか、読めない display で一覧が落ちないか。release.sh の 0/6 でも回る）。
  iPhone: `BGURU_DEMO=1 BGURU_DEMO_TAB=timeline BGURU_DEMO_TIMELINE_CHECK=1`

## 上下反転のチェック（リリースの前に）

## 長いスレッドのチェック（リリースの前に）
スレッドを開いているとパネルが固まる報告（2026-10-21・22）を受けて、まずスレッドを開いたままタイムラインの再読み込みを

その間に写真・返信欄・リアクション）、次にデモの 300 件の返信つきスレッドを開き、開いている途中からスクロール・上まで・下へ戻る・

```bash
native/mac/scripts/release.sh 0.1.0              # 署名 → DMG → 公証 → staple → Gatekeeper 確認
native/mac/scripts/release.sh 0.1.0 --no-notarize  # 署名付き DMG だけ（手元確認）
```
- 署名: Developer ID Application: Kohichi Aoki (F9349EVF2K)、Hardened Runtime、secure timestamp
- ユニバーサル（Apple シリコン + Intel）。スクリプトが lipo で確認する
- 公証: キーチェーンのプロファイル `notary`（`xcrun notarytool store-credentials notary` で一度だけ登録）
- スクリプトは、Developer ID 署名・Hardened Runtime・timestamp を確認し、開発用の仕組み
  （BGURU_DEV_TOKEN）がリリース版に入っていないことも確認する。成果物は `native/mac/dist/`（git 管理外）

## 会員への配布（B-guru 右サイドバーのダウンロード）と自動アップデート
```bash
native/mac/scripts/release.sh <版> && native/mac/scripts/publish.sh <版> "<今回の変更点>"
```
- 自動アップデートは Sparkle 2.9.6（固定）。0.1.4 以降を入れた Mac は 6 時間ごとに確認し、新しい版があれば
  「アップデートがあります」と出る（右クリックメニュー / ⋯ の「アップデートを確認…」でも）
- appcast: `/api/download/mac/appcast.xml`（会員 or アプリのトークン。Sparkle にトークンをヘッダで持たせる）
- 更新ファイルは EdDSA 署名必須。秘密鍵はこの Mac のログインキーチェーン（Sparkle の generate_keys で作成）。
  **失うと以後アップデートを出せない**ので `generate_keys -x 書き出し先` でバックアップしておくこと
- release.sh は Sparkle の中身（XPC サービス・Autoupdate・Updater.app）を Developer ID で署名し直す
公証済み・staple 済みかを確認してから、本番サーバーの `/home/ubuntu/bsm-downloads/` に DMG を置き、
最後に `mac.json`（版・サイズ・SHA-256）を差し替える。サイトは `/api/download/mac`（会員のみ）で配り、
右サイドバー最上部のカード（Mac のデスクトップでのみ表示）から落とせる。新しい版はデプロイ不要。
